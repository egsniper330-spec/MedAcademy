# Android root/runtime hardening + Play Integrity enforcement

Status: implemented in this change set. Android-only work; iOS is out of scope and
its existing jailbreak/App-Attest paths are untouched.

Related: [PLAY_INTEGRITY_SETUP.md](PLAY_INTEGRITY_SETUP.md) (operator setup),
[SECURITY_TEST_MATRIX.md](SECURITY_TEST_MATRIX.md) (device matrix),

## 1. What already existed (audited, not rebuilt)

The app already had a substantial security stack. Anything below was verified in
the repository before deciding on changes; nothing here is new.

| Layer | Where | Notes |
|---|---|---|
| Native security module (Kotlin, generated by `plugins/withSecurityModule.js` at prebuild) | `SecurityModule.kt` | Root/Magisk/Zygisk/Frida/Xposed/emulator/overlay/VPN/proxy/debug/tamper/signature checks, plus a batch `getSecurityFlags()` |
| C++ core `libmedasec` (`plugins/withSecurityModule.js` → `medasec_core.cpp`) | JNI | `/proc` inspection: anonymous exec mappings, hook-lib names, thread-name indicators, kernel net tables |
| Root-framework artifact probe | `SecurityModule.probeRootArtifacts()` | stat() by errno (PRESENT vs EACCES), **DenyList-resistant** |
| Signed device evidence | `SecurityEvidenceService.php`, `src/lib/deviceKey.ts` | Keystore-signed, challenge-bound payload; server verifies signature and decides assurance |
| Play Integrity | `IntegrityService.php`, `IntegrityController.php`, `src/lib/integrityClient.ts` | Server-side `decodeIntegrityToken`, requestHash binding, verdict rows, tiered `assertActionAllowed()` |
| Client risk model + gates | `src/lib/security.ts`, `securityStateModel.ts`, `SecurityContext.tsx` | Weighted findings, policy evaluation, 30 s re-check, startup gate |
| PDF watermarking | `PdfWatermarkService.php`, `PdfWatermarkBaker.php`, `MaterialDeliveryController.php` | Mandatory per-student personalisation, vector (TCPDF/FPDI) and raster (Ghostscript/Imagick) modes, private bucket, short-lived delivery token, live re-authorisation |

Distribution: Google Play **and** direct install; `material_pdf`, `vdo_otp`,
`redeem`, `device_bind` are the sensitive operations the server can gate.

### Threat model (concise)

| Adversary | Capability | What actually raises their cost |
|---|---|---|
| Student with a rooted/hidden device | Magisk DenyList, Shamiko, LSPosed, Frida gadget; patched APK | **Server-side** decisions bound to Google-verified evidence; client signals are advisory |
| Repackaged APK | Re-signed, smali-patched to return "clean" | Certificate digest pinning (Play Integrity), Keystore-signed evidence, server policy |
| Leaked PDF | Re-upload, screenshot, PDF-editor watermark deletion | Per-student personalised copy, watermark painted into page content, issuance records |

Explicitly **not** assumed: that any local check cannot be bypassed. A hooked
`stat()`/`openat()` or a patched `detectRoot()` defeats every local signal. The
design goal is layered *cost*, with the backend as the only authority.

## 2. Defects found and fixed

### 2.1 Two native root checks could never fire (Android)

- `Runtime.exec("which", "su")` — Android's toybox has no `which`, so the exec
  always threw and the check resolved to `false` on every device, rooted or not.
  It also spawned a shell from the app process, which is itself an
  instrumentation signal.
- `/proc/modules` scanned for `"zygisk"` — Zygisk is a **userspace** Zygote
  injection and never registers a kernel module; Android kernels expose
  `/proc/modules` empty or absent.

Both looked like coverage and provided none. This is the most common way a
"hardened" client is weaker than it appears.

### 2.2 Play Integrity certificate comparison could never match

`appIntegrity.certificateSha256Digest` is **base64url**; `security_config.expected_cert_sha256s`
holds **hex**. The previous code ran the base64url value through a hex-shaped
normaliser (`str_replace(':','')`), so:

- with a pin configured → **every genuine client was rejected** (or, on the
  `enforce` tier, locked out), and
- with no pin → the check silently did nothing.

Both are now normalised to lowercase hex (`IntegrityService::normalizeCertDigest`,
applied to Google's value *and* to the pinned values, so either encoding in the
DB works).

### 2.3 Integrity-hash cache was not bound to an action

`integrityClient.ts` cached one hash globally. The hash is bound to a single
action server-side, so a second protected action inside the 4-minute window
reused the first action's hash — the backend found no verdict row for
`(user, hash, action)` and, on `enforce`, rejected a **genuine** client. The
cache is now keyed by action (`peekIntegrityHash(action)` requires it).

### 2.4 PDF issuance was not covered by the integrity policy

`MaterialDeliveryController::pdfUrl` — the only endpoint that can mint a
student-identifiable document — had no `assertActionAllowed()` call, although
playback, redemption and device binding did. Now enforced under a new
`material_pdf` action (tier `log_only` by default, like every other action).

## 3. Implemented changes

### 3.1 Native root detection (Android)

All in `plugins/withSecurityModule.js` (the Expo Config Plugin source of truth —
`android/` is regenerated by prebuild, so generated files are never hand-edited).

1. **`suOnPath()`** — stat-based PATH scan replacing the dead `which su` exec.
   `PRESENT` and `DENIED` (EACCES) count; `UNKNOWN` does not. No subprocess, no
   exec permission, bounded to 32 PATH entries / 6 results.
2. **`inspectMountView()`** — parses `/proc/self/mountinfo` (bounded to 512
   lines, 2 s memo so one `getSecurityFlags()` batch parses it once) and reports:
   - `root_overlay_on_system` — overlayfs over `/system|/vendor|/product|/odm|/system_ext`
     backed by `/data` (or any magisk-named path);
   - `root_module_mount` — a system path bind-mounted from `/data`, or a
     module-named mount, or a mount point under `/data/adb`;
   - `magisk_debug_ramdisk` — source under `/debug_ramdisk`.
   The **whole line** is scanned: `upperdir=`/`lowerdir=` live in the per-mount
   OPTIONS field, not in the fstype/source fields (an earlier version of this
   rule missed every Magisk overlay because of exactly that).
3. **False-positive contract** — ordinary mounts are *not* evidence: tmpfs, the
   app's own data dir, a plain ext4 `/data`, a read-only `/system`, and a
   vendor overlay that is **not** backed by `/data`. Verified by tests.
4. **DenyList-resistant artifact set extended** — `modules_update`,
   `post-fs-data.d`, `service.d`, `ksud` (KernelSU), `apd` (APatch),
   `debug_ramdisk/magisk`, all probed by errno so `EACCES` still reads as
   "exists but root-only".
5. **Wiring** — `detectRoot()` and `detectMagisk()` now consume both new signals;
   `checkZygisk()` reports mount evidence instead of the dead modules read.
6. **Evidence surface** — `getRootArtifactEvidence()` additionally returns
   `mountEvidence`, `mountSamples`, `suOnPath`, `systemWritable`; the TS type
   `NativeRootArtifactEvidence` declares them. These are state/paths only — no
   URL, token or identity.

Not done deliberately: no `ptrace(PTRACE_TRACEME)` anti-debug (breaks debugging
and legitimate tooling, trivially bypassed), no aggressive emulator blocking
(already evidence-graded), no new RASP SDK (see §5).

### 3.2 Server-side Play Integrity

`backend/src/Services/IntegrityService.php`:

- **Freshness** — `requestDetails.timestampMillis` must be present, numeric, at
  most 10 minutes old and no more than 60 s in the future; otherwise the request
  is rejected. A missing/garbage timestamp fails closed.
- **Policy fields** — `device_verdicts` (default: `MEETS_DEVICE_INTEGRITY` or
  `MEETS_BASIC_INTEGRITY`, unchanged behaviour, now tunable), and
  `require_licensed` (**default false** — this app also ships outside Play, so
  `UNLICENSED` is legitimate here).
- **Failure telemetry** — every rejection logs `play_integrity_failed` with the
  failing check (`package_mismatch`, `request_hash_mismatch`,
  `stale_or_undated_token`, `app_not_recognized:*`, `certificate_mismatch`,
  `device_verdict:*`, `not_licensed`). Clients still see only
  "Integrity verification failed".
- **Google error classification** — `429`/`5xx`/transport = transient
  (retryable), other `4xx` = permanent; both fail closed with distinct signals.
- **OAuth caching** — the service-account access token is cached until ~60 s
  before expiry instead of minting a JWT + OAuth round-trip on every protected
  call (a burst of PDF issuances multiplied Google traffic and latency for no
  security benefit).

### 3.3 Enforcement coverage

| Operation | Endpoint | Action key | Default tier |
|---|---|---|---|
| Video playback token | `POST /vdocipher-otp` | `vdo_otp` | log_only |
| Redeem code | `POST /redeem-code-redeem` | `redeem` | log_only |
| Device binding | `POST /devices/register` | `device_bind` | log_only |
| Financial | — | `financial` | log_only |
| **Personalised PDF issuance** | **`POST /materials/pdf-url`** | **`material_pdf`** | **log_only** |

The client sends both layers for issuance (`X-Integrity-Hash` + signed evidence)
via `buildProtectedCallHeaders('material_pdf', body)`; a client that strips them
gains nothing — `enforce` requires a server verdict row that only Google's
decoded payload can create.

`/materials/pdf` (the streaming half) is intentionally **not** header-gated: it
is opened by a URL from the PDF viewer and its authority is the short-lived
token, re-validated against live DB state (permission, download flag, enrollment,
publication) at stream time.

### 3.4 PDF personalisation (audited; one gap closed)

Already present and verified: mandatory per-student personalisation for every
role, private source bucket, storage endpoints refuse lesson-material PDFs
(`material_delivery_required`), 300 s delivery token bound to material + student +
intent, live re-authorisation, `no-store`, per-variant cache rows
(`lesson_material_pdfs`), delivery audit rows, fail-closed when no renderer is
available, watermark painted into page content (vector) with an optional
rasterised mode, per-page seeded placement.

Change made: issuance is now also covered by the integrity policy (§3.3).

`validate-native-build.js` earned its place: the first version of the Kotlin
doc-comments used backticks, which closed the surrounding JS template literal and
made the whole config plugin unparseable — every prebuild would have failed. The
plugin-require check caught it before any device run; the Kotlin was fixed and the
validator now passes.

The new suite pins, against files on disk:

- the dead probes are gone and the replacements are wired;
- the mount rule flags each root-framework shape and **not** the five ordinary
  shapes (mirror test of the rule + static assertions on the Kotlin conditions);
- base64url and hex certificate digests normalise to the same value, and
  garbage does not;
- freshness, licensing default, failure telemetry, OAuth cache;
- `material_pdf` is a protected action end to end (policy → evidence whitelist →
  controller → client headers → per-action cache);
- the three modified PHP files still parse (`php-parser` AST).
- the Config Plugin still loads (the failure mode that would abort prebuild).

### 4.1 Honest limits of this verification

- **No Android build or device run.** No Android SDK/emulator in this
  environment, so the Kotlin was not compiled and no rooted/DenyList/hooked
  device was tested. The template validator plus static tests are what exist;
  the device matrix in §6 is unexecuted.
- **No PHP runtime.** `php` is not installed here; PHP was validated by AST
  parse plus static assertions, not by executing `IntegrityService`. The
  normalisation algorithm is exercised through a JS mirror.
- **Play Integrity cannot be exercised** without Play credentials, a
  Play-distributed build and a certified device.
- The first full run reported 104 passed / 2 failed. Both failures were test
  brittleness, not behaviour: one asserted a re-aligned PHP table via an exact
  spacing match, the other read `detectRoot()` through a fixed 1200-byte window
  that the new checks pushed the su list past. Both assertions were corrected
  (whitespace-insensitive match; slice to the next member, plus an explicit
  assertion that the DenyList probe still runs first) and the full suite then
  passed 106/106.

## 5. Rejected / deferred, and why

| Candidate | Decision | Reason |
|---|---|---|
| RootBeer | Rejected | Overlaps existing checks; its own README documents the limits (name lists, `su` renaming, systemless root) — no capability gain |
| Talsec freeRASP / SecureVale RASP | Rejected | Redundant with the existing native module + server model; freemium/binary components, extra Play-policy surface, unverifiable native provenance here |
| `ptrace` self-attach anti-debug | Rejected | Breaks debugging and some legitimate tooling; bypassed by hooking; already covered by `Debug.isDebuggerConnected()` and `TracerPid`-class evidence |
| Aggressive emulator blocking | Rejected | The existing emulator check is already evidence-graded after a documented false-positive incident |
| Play Integrity `MEETS_STRONG_INTEGRITY` / licensing enforcement by default | Deferred (configurable) | Would block legitimate direct-install and older-but-genuine devices; enable per telemetry |
| Full-page rasterisation as the default PDF mode | Deferred (available) | Kills text selection/search/accessibility and inflates processing cost; vector mode preserves text and is the current default |
| Tardos / forensic fingerprint codes | Deferred | No maintained PDF-embedding + detector implementation; needs a validated channel and false-positive study |
| Random per-issuance ID embedded in the PDF | Deferred | Current trace code + `lesson_material_pdfs` + delivery audit already map a copy to recipient and time; per-issuance uniqueness needs a pipeline change with its own testing |

## 7. Deployment

Backend files changed (upload in this order):

1. `backend/src/Services/IntegrityService.php`
2. `backend/src/Services/SecurityEvidenceService.php`
3. `backend/src/Controllers/MaterialDeliveryController.php`

No migration, no new environment variable, no new dependency. Order matters only
in the sense that all three should land together: the controller now calls into
`IntegrityService`, and `material_pdf` must be known to both services.

Client: rebuild via prebuild/EAS (the Kotlin comes from the Config Plugin).
`android/` must be regenerated — never hand-patched.

Rollout: everything is `log_only` by default. Enable enforcement per action when
the logs show the real distribution:

```sql
-- security_config.extras
UPDATE security_config
SET extras = JSON_SET(extras, '$.play_integrity.actions.material_pdf', 'enforce'),
    security_version = security_version + 1
WHERE is_active = 1;
```

Watch `security_events` for `play_integrity_failed` reasons before and after.

## 8. Residual risk

- Local detection is advisory: a hooked `stat()`/`openat()`/`mountinfo` read
  defeats every client signal. Only the server verdict is authoritative.
- Play Integrity is not a root detector: an empty device verdict means "not
  verified", not "rooted"; a positive verdict does not prove a clean environment.
- A stolen, valid verdict row is useless cross-user/cross-action (bound to
  `(user, action, hash)` with a 60–900 s TTL), but a compromised *legitimate*
  device can still request and use its own evidence.
- Vector watermarks survive naive editor deletion but not re-rendering,
  reconstruction or targeted content-stream editing. Attribution is an aid, not
  proof.
- No independent penetration test has been performed on this change set.
